The PerfectForwarding test asserted `captured.empty()` after `captured` had been moved into the lambda's init-capture. A moved-from std::vector is only in a valid but unspecified state, so that assertion relied on unspecified behaviour. The use-after-move assertion has been replaced with a check inside the cleanup lambda that the moved-in vector still holds its three elements (`EXPECT_EQ(captured.size(), 3U)`), which runs when the cleanup fires at scope exit and verifies that the data was forwarded into the callable.
