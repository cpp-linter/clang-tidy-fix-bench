For the %hhd/%hhi printf path the vararg is narrowed to signed char and then stored into the 64-bit unsigned value, which is later reinterpreted as signed (fm.is_signed) when printing. Sign extension is the intended behaviour here, so casting to unsigned char as the check suggests would be wrong. Instead the signed char is now explicitly widened to uacpi_i64 before the assignment, making the sign extension explicit; the stored bit pattern is identical to before.
