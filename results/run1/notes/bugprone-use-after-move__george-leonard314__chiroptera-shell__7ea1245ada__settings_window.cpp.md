The call `openWidgetInspectorEditor(barWidgetLanePath(..., widgetName), std::move(widgetName))` reads `widgetName` in one argument and moves it in another; because function-argument evaluation order is unspecified, the second parameter's move construction could happen first and the lane path would be computed from an empty name. This is a real bug, so the lane path is now computed into a local `lanePath` before the call, and both `lanePath` and `widgetName` are then moved into `openWidgetInspectorEditor`.
