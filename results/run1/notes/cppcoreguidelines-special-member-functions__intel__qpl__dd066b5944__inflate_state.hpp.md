The hardware specialization of inflate_state already defaulted its copy constructor, deleted copy assignment and had a custom destructor, but declared no move operations. I declared the move constructor as noexcept = default and deleted move assignment, matching the copy operations. The move constructor has to stay available: create() returns a named local by value, and a deleted move constructor would make that return ill-formed. The defaulted move does the same memberwise transfer of pointers and PODs that the implicit copy did before, so behaviour does not change.
