This was a real bug. `openWidgetInspectorEditor(barWidgetLanePath(..., widgetName), std::move(widgetName))` reads and moves `widgetName` in the same call, and C++ does not fix the order in which function arguments are evaluated. A by-value parameter could therefore be move-constructed from `widgetName` before `barWidgetLanePath` reads it, leaving it an empty string. The lane path is now computed into a local first, then both values are passed in, which guarantees the read happens before the move.
