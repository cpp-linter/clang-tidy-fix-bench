The disabled specialisations `basic_mask<T, Abi, false>` and `basic_vec<T, Abi, false>` delete the default/copy operations and the destructor; the move constructor and move assignment operator are now deleted as well, which completes the set. Those moves were already not declared because of the user-declared copy operations, so nothing changes. `where_expression` deleted its copy operations; it now also deletes the move constructor and move assignment and declares a defaulted destructor. `where()` returns it with `return {m, v};` (copy-list-initialisation, which needs no copy or move), so behaviour is unchanged.
